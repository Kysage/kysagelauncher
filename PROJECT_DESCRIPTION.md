# OBSIDIAN Launcher

## 1. Назначение проекта

OBSIDIAN Launcher — настольный лаунчер Minecraft на Electron. Приложение сочетает современный интерфейс в темной теме с настоящей загрузкой и запуском ванильного Minecraft через официальные манифесты Mojang.

Лаунчер рассчитан прежде всего на Windows, но часть серверной логики использует кроссплатформенные правила путей, библиотек и аргументов JVM.

## 2. Основные возможности

- запуск настоящего Minecraft, а не только демонстрационного интерфейса;
- получение списка версий из официального манифеста Mojang;
- создание отдельных сборок с именем, версией Minecraft и загрузчиком;
- отдельная папка клиента, модов и конфигурации для каждой сборки;
- поиск и фильтрация версий;
- автоматическая загрузка клиента, библиотек, natives и ресурсов;
- повторное использование уже загруженных файлов;
- проверка файлов по SHA-1, включая клиентский JAR;
- расчет совместимых аргументов JVM и аргументов самой игры;
- автоматическое определение подходящей Java;
- локальный оффлайн-профиль с ником и UUID;
- локальная загрузка PNG-скина (64×64 или 64×32) с предпросмотром и автоматическим включением ресурс-пака для офлайн-сборок;
- настройка выделяемой памяти отдельно для каждой сборки;
- выбор Java вручную;
- выбор отдельной папки игры;
- живой журнал stdout/stderr Minecraft;
- отображение прогресса скачивания;
- выбор Vanilla, Forge, Fabric, Quilt или NeoForge при создании сборки;
- установка загрузчиков и управление JAR-модами в выбранной сборке;
- поиск модов и модпаков CurseForge с фильтрами версии Minecraft и загрузчика, включая каталог готовых сборок в окне создания профиля;
- установка файлов модов с проверкой SHA-1/MD5 и импорт CurseForge-модпаков из ZIP;
- автоматическое открытие страницы CurseForge, когда автор запрещает прямое скачивание;
- отмена загрузки и остановка запущенной игры;
- собственные кнопки окна: свернуть, развернуть и закрыть;
- сохранение настроек между запусками;
- демо-режим для просмотра интерфейса без скачивания игры;
- создание скриншотов экранов лаунчера.

## 3. Интерфейс

### Главная страница

Главная страница является основным рабочим экраном. На ней находятся:

- крупный hero-блок с процедурной сценой Minecraft;
- выбранная версия игры;
- кнопка запуска или отмены текущей загрузки;
- индикатор прогресса и описание текущего этапа;
- карточка профиля Steve;
- настройка выделяемой памяти;
- информация о найденной Java;
- путь к папке игры;
- краткая статистика выбранной версии;
- журнал запуска в нижней части окна;
- статусные индикаторы Java, памяти, журнала и папки игры.

Во время загрузки кнопка запуска заменяется на кнопку «Отменить». После успешного запуска интерфейс показывает состояние работающей игры и позволяет ее остановить.

### Страница сборок

На странице сборок можно создать профиль, задать имя, версию Minecraft и загрузчик или переключиться между существующими профилями.

Кнопка «Настроить» открывает параметры отдельной сборки: имя, выделенную память, каталог и управление её модами. Управление модами открывается с активным профилем, так что CurseForge-загрузки и локальные JAR устанавливаются именно в его папку `mods`.

Версии Minecraft загружаются в форме создания профиля. У каждого профиля отдельный игровой каталог, поэтому моды и настройки не смешиваются. Старые настройки с выбранной версией при первом запуске мигрируют в профиль «Моя сборка».

### Страница настроек

В настройках можно изменить:

- ник оффлайн-профиля;
- количество памяти в мегабайтах;
- путь к Java;
- папку игры;
- отображение журнала запуска;
- поведение лаунчера после запуска игры.

Для Java и папки игры предусмотрен выбор через системный диалог. Введенный путь к Java можно проверить отдельной проверкой совместимости.

### Журнал запуска

Журнал отображает события загрузки и запуска в реальном времени. Сообщения разделяются по типам потоков и состояния:

- обычный вывод;
- предупреждения;
- ошибки;
- успешные события.

Журнал можно раскрывать, скрывать и очищать. Он получает сообщения от основного процесса Electron через IPC.

## 4. Визуальная система

Интерфейс использует собственную темную визуальную систему OBSIDIAN Launcher:

- темный графитовый фон;
- лаймовый акцент `#8bf26b`;
- компактная сетка отступов с шагом 4 пикселя;
- шрифты Bahnschrift/Segoe UI;
- тонкие границы и полупрозрачные панели;
- скругления небольшого радиуса;
- процедурная SVG-графика без внешних изображений.

Сцена на главной странице, логотип, плавающие острова, кубы и аватары генерируются кодом в `src/renderer/art.js`. Это позволяет запускать проект без дополнительного набора графических файлов.

## 5. Технологии

- Electron 45.4.1;
- Node.js 18 или новее;
- ванильные HTML, CSS и JavaScript;
- `adm-zip` для работы с архивами Minecraft;
- официальные JSON-манифесты Mojang;
- Java Runtime Environment для запуска игры;
- Electron IPC для связи renderer-процесса с основным процессом.

Сборщик и frontend-фреймворк не используются. Renderer можно открыть напрямую в браузере для просмотра демо-интерфейса.

## 6. Архитектура

### Основной процесс Electron

Файлы в `src/main/` отвечают за системную часть приложения:

- `main.js` — создание окна, обработка аргументов запуска, IPC, системные диалоги, скриншоты и управление состоянием игры;
- `minecraft.js` — загрузка манифеста и файлов Minecraft, проверка SHA-1, правила ОС, подготовка аргументов и запуск Java-процесса;
- `loaders.js` — получение совместимых версий и установка Forge/Fabric/Quilt/NeoForge с обнаружением созданного профиля;
- `mods.js` — управление JAR-модами, импорт файлов CurseForge и модпаков;
- `offline-skin-pack.js` — локальный ресурс-пак с офлайн-скином и его включение для профиля;
- `curseforge.js` — CurseForge API: поиск проектов, файлы и ссылки скачивания;
- `download-manager.js` — потоковая загрузка файлов, редиректы CDN, прогресс и проверка хешей;
- `config.js` — встроенный ключ CurseForge и загрузка `.env` с приоритетом переменных окружения;
- `modrinth.js` — прежний сервис Modrinth, оставленный для совместимости;
- `java.js` — поиск Java в PATH, через `JAVA_HOME`, ручной путь и установленные рантаймы официального лаунчера;
- `auth.js` — создание локального UUID и данных оффлайн-профиля;
- `store.js` — чтение и сохранение настроек, списка сборок и выбранного профиля;
- `preload.js` — безопасный мост между renderer и основным процессом.

### Renderer-процесс

Файлы в `src/renderer/` отвечают за отображение и взаимодействие:

- `index.html` — разметка главной страницы, менеджера сборок, формы создания, настроек и журнала;
- `styles.css` — тема, layout, панели, кнопки, формы, адаптивные состояния и анимации;
- `art.js` — генерация SVG-сцены, логотипа, кубов и аватаров;
- `app.js` — состояние интерфейса, навигация, формы, прогресс, журнал, запуск и демо-мост.

### Скрипты

- `scripts/doctor.js` — диагностический end-to-end запуск Minecraft;
- `scripts/probe.js` — вспомогательный скрипт проверки поведения демо-сценария.

## 7. Процесс запуска Minecraft

При запуске выбранной версии выполняются следующие этапы:

1. Лаунчер читает сохраненные настройки и выбранную версию.
2. Загружается общий манифест версий Mojang.
3. Проверяется JSON-файл конкретной версии.
4. Для версии подготавливаются клиент, библиотеки, natives и ресурсы.
5. Уже существующие файлы проверяются и повторно не скачиваются без необходимости.
6. Для скачиваемых файлов создаются каталоги и выполняется проверка контрольных сумм.
7. Применяются правила конкретной операционной системы.
8. Формируются аргументы JVM, classpath и аргументы игры.
9. Создается локальный оффлайн-профиль с ником и UUID.
10. Запускается процесс Java.
11. stdout и stderr Minecraft передаются в журнал лаунчера.
12. При завершении игры обновляется состояние интерфейса.

Лаунчер не завершает Minecraft автоматически при закрытии окна лаунчера. Игра работает отдельным дочерним процессом.

## 8. Поиск Java

Java ищется в нескольких местах:

- пользовательский путь из настроек;
- `JAVA_HOME`;
- PATH операционной системы;
- стандартные установленные JDK/JRE;
- рантаймы официального Minecraft Launcher.

Для Minecraft 26.x требуется Java 21–25 в зависимости от версии. Лаунчер показывает найденную версию Java и ее совместимость до запуска.

## 9. Оффлайн-профиль и авторизация

Сейчас используется локальный оффлайн-профиль. По умолчанию профиль называется `Steve`, но ник можно изменить в настройках. UUID создается детерминированно на основе имени профиля. Можно выбрать PNG-скин размером 64×64 или 64×32: лаунчер сохранит текстуру и покажет предпросмотр в интерфейсе, а для каждой сборки создаст и автоматически включит локальный ресурс-пак без модов. Он переопределяет стандартные текстуры персонажей без авторизованного скина только на этом компьютере; текстура не загружается в аккаунт и не видна другим игрокам.

Microsoft, Xbox и Mojang-авторизация пока не подключены. Поэтому лаунчер подходит для локальной игры и одиночного режима, но не обеспечивает полноценный вход на серверы, требующие лицензионную авторизацию.

## 9.1. Загрузчики и моды

При создании сборки можно выбрать Vanilla, Forge, Fabric, Quilt или NeoForge, либо открыть вкладку каталога готовых модпаков CurseForge. Для загрузчика сначала выбирается версия Minecraft, затем совместимая версия загрузчика; Forge и NeoForge устанавливаются официальными инсталляторами, Fabric и Quilt — через официальные метаданные. JAR-моды устанавливаются в папку `mods` выбранной сборки. В каталоге CurseForge можно искать моды или модпаки; версия Minecraft и загрузчик подставляются из активной сборки и при необходимости меняются вручную. Импорт модпака устанавливает указанные в его манифесте загрузчик и Minecraft-версию, скачивает перечисленные файлы и копирует `overrides` в профиль. При установке показываются отдельные этапы скачивания архива, установки загрузчика, получения метаданных, загрузки модов и копирования overrides. API-ключ CurseForge встроен в `src/main/config.js`, поэтому каталог работает сразу; переменная окружения `CURSEFORGE_API_KEY` или локальный `.env` могут переопределить его. Ключ не доступен renderer-процессу. Логотипы модов загружаются с CDN CurseForge, а для установленных JAR-файлов иконки извлекаются из `fabric.mod.json`, `quilt.mod.json`, `mods.toml` или `mcmod.info`.

## 10. Хранение данных

По умолчанию данные сохраняются в каталоге:

```text
%APPDATA%\\.obsidian-launcher
```

Основные места хранения:

```text
%APPDATA%\\.obsidian-launcher\\settings.json
%APPDATA%\\.obsidian-launcher\\instances\\<id>
%APPDATA%\\.obsidian-launcher\\versions
```

Клиент, моды и настройки профиля находятся в его отдельной папке. Кэш версий, библиотек, natives и ресурсов остается в общем каталоге данных лаунчера. Старые настройки с выбранной версией мигрируют в профиль «Моя сборка» с сохранением прежней папки игры.

## 11. Демо-режим

Демо-режим позволяет открыть интерфейс без реальных сетевых запросов и запуска Java. В нем используются тестовые данные:

- список версий;
- информация о Java;
- пути к каталогам;
- имитация скачивания;
- тестовые строки журнала;
- состояния подготовки, загрузки, запуска и остановки.

Демо-режим удобен для проверки дизайна, создания скриншотов и просмотра интерфейса на компьютере без загруженных файлов Minecraft.

В браузере демо активируется автоматически, если Electron API недоступен. В Electron его можно включить аргументом `--demo`.

## 12. Скриншоты и режимы просмотра

Основные команды скриншотов:

```bash
npx electron . --screenshot shots/home.png
npx electron . --screenshot shots/versions.png --view=versions
npx electron . --screenshot shots/settings.png --view=settings
npx electron . --screenshot shots/progress.png --demo --autoplay --wait=8000
```

Поддерживаемые аргументы:

- `--screenshot <path>` или `--screenshot=<path>` — сохранить окно в PNG;
- `--view=home|versions|settings` — открыть нужный экран;
- `--demo` — включить демонстрационные данные;
- `--autoplay` — автоматически начать демонстрационный запуск;
- `--wait=<milliseconds>` — задержка перед созданием скриншота.

Обычный запуск `electron .` не включает режим скриншота.

## 13. Установка и запуск

Установить зависимости:

```bash
npm install
```

Запустить лаунчер:

```bash
npm start
```

Открыть демонстрационный режим:

```bash
npx electron . --demo --autoplay
```

Запустить диагностику настоящего Minecraft:

```bash
npm run doctor
```

Сделать обычный скриншот:

```bash
npm run shot
```

Первый запуск выбранной версии может скачать около 500 МБ клиента, библиотек и ресурсов. После загрузки повторный запуск использует локальный кэш.

## 14. Проверка работоспособности

Диагностический скрипт проверяет полный путь от получения списка версий до запуска Minecraft. В текущей реализации уже проверен запуск Minecraft 26.3 на Java 25.0.5.

Ожидаемые сообщения об ошибках Realms или `Failed to fetch user properties` при оффлайн-профиле не означают поломку загрузчика. Они связаны с отсутствием Microsoft/Xbox-токена.

## 15. Ограничения текущей версии

- Microsoft/Xbox-авторизация не реализована;
- ресурсы версии загружаются полностью при первом запуске;
- при запрете прямого скачивания CurseForge-файла его нужно загрузить вручную в папку «Загрузки»; лаунчер сам найдёт файл, проверит размер и хеш и не даст продолжить, пока все обязательные файлы не будут на месте;
- отдельная production-упаковка и установщик пока не настроены;
- сообщения Chromium о невозможности создать GPU-диск-кэш могут появляться в Windows из-за блокировки или прав доступа, но обычно не мешают работе приложения.

## 18. Текущий статус

Проект представляет собой рабочий прототип лаунчера с запуском Vanilla/Forge/Fabric и управлением JAR-модами. Основной пользовательский сценарий реализован: выбрать тип сборки и версии, настроить Java и память, скачать необходимые файлы и запустить игру через локальный оффлайн-профиль.
